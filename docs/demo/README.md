AI 历史记录的模型名为 `demo-fixture`，摘要和审核文字标注“演示”，不代表实际模型调用。初始化不会调用付费 AI 接口。原有 AI 配置、API Key、提示词模板、敏感词库和 RBAC 权限配置保留，实际 AI 能否使用仍取决于原有服务配置。

## 推荐演示路线

1. **读者 Web / App**：打开首页 → 分类与榜单 → 《九霄问道》详情与封面 → 阅读一章 → 登录 `reader01` 查看书架、阅读历史与进度 → 查看书評评分及作者回复。
2. **作者端**：登录 `author01` → 两本作品 → 大纲树 → 打开章节草稿并编辑 → 查看待审核章节 → 演示上传封面及作品信息编辑。
3. **管理员端**：使用原管理员 → 看用户与角色 → 审核两本待审作品 → 章节审核 → 作者申请 → 评论与违禁审核 → 公告草稿 → AI 用量统计和模型配置。
4. **补充流程**：`author06` 的《听雪刀》为草稿；`author07` 的《把春天寄给你》、`author08` 的《深蓝航线》待审核；`author09` 的《云边修理铺》已驳回；`author10` 的《明日开门》已下架。`reader01` 的书架和历史包含下架书，便于展示占位处理。

## 文件与封面

- `books.json`：20 本作品的标题、笔名、简介、人物、题材与生成画面描述。
- `covers/01.jpg` ～ `covers/20.jpg`：生成并优化后的原创封面，按作品编号对应。
- `cover-preview.jpg`：20 张封面的总览图。
- `cover-prompts.md`：使用内置 imagegen 工具的提示词模板与逐张画面要求。
- `cover-urls.json`：通过现有封面上传接口返回的 `/uploads/cover/...` 地址。
- `last-run.json`：本次初始化后的账号与作品编号、数据数量；不含管理员密码或 AI 密钥。
- `verification.json`：数据库、接口、封面和搜索索引验证结果。

封面通过管理员调用现有作者上传接口写入配置的共享上传目录。Web、H5 和 App 共用网关 `/uploads/**` 路由。更换部署环境时重新运行上传脚本，不能只搬运数据库里的旧 URL。

## 重新初始化

这些脚本只用于开发演示库。默认读取 `novel-content` 的 `application-dev.yml`，且要求目标库表结构与项目的 22 张表一致。

```powershell
python -m pip install --target .demo-tools -r docs/demo/requirements.txt
python docs/demo/inspect_environment.py
python docs/demo/upload_covers.py
python docs/demo/seed_demo.py
python docs/demo/seed_demo.py --apply
python docs/demo/verify_demo.py
```

`seed_demo.py` 默认仅检查。只有 `--apply` 会删除旧业务数据和非管理员账号，并重新生成演示数据。管理员密码若不是初始默认值，在本地设置 `DEMO_ADMIN_PASSWORD` 环境变量，脚本不会更改它。`DEMO_GATEWAY` 可覆盖本机网关地址。

每次执行 `--apply` 都先在 `.backup/demo-日期-时间/` 写入完整 22 表快照、SQL 数据恢复文件和校验哈希，再通过单个事务清空、插入并检查关联与计数。失败会回滚数据库事务；不会使用 `TRUNCATE`。管理员所有原字段和角色关联保留。

备份含账号哈希和原有配置密钥，目录已被 Git 忽略。恢复 SQL 适用于相同表结构，文件名为 `restore.sql`，执行前应先备份当前状态。Redis 删除的缓存另存为 `redis-cache.json`，可以按需恢复，但通常恢复数据库后清缓存、重建搜索索引即可。

初始化会失效被删除用户的登录令牌，清理本项目的旧内容缓存，并通过管理员搜索重建接口刷新 ES。管理员原登录令牌继续保留。

本次初始化已通过 16 组数据库与实际接口检查：全部 20 个新账号登录、管理员字段与角色保留、20 张图片经网关与 Web 代理读取、读者列表详情正文、分类榜单公告、书架历史及下架占位、书评回复、作者大纲、管理统计与审核队列、Redis 点赞一致性、ES 重建与搜索。搜索索引按项目设计包含 20 本各状态作品，读者搜索只返回其中 15 本已上架作品。此验证不包含 App 手机实机界面。
