# 写作 Agent 扩展使用与部署

本次完成样文分析、个人 Skill、MCP Client、草稿分支与三方合并、累计摘要、自动索引及删除传播。工程验证结果见 [JSON 报告](evals/writing-agent/extensions-verification.json)。模型生成质量与真实外部服务效果尚未验收。

## 作者入口

打开作品编辑页，点击底部「写作扩展」，进入 `/author/novel/<作品ID>/writing-lab`。右侧写作聊天区的 Skill 按钮选择规则，「资料」中选择文风档案和累计摘要，「工具」中开关具体 MCP 工具。更改配置不会自动重写已有草稿。

### 助手自定义指令

右侧写作助手顶部「助手设置」提供个人默认与当前作品两个范围，支持保存和恢复默认。默认内容来自 `novel-ai/src/main/resources/writing/assistant-default.md`，作者可填写角色、描写习惯、用词和修改方式，每份最多 6000 字。当前作品启用覆盖时使用本书指令，否则继承个人默认；未启用个人自定义时使用平台默认。恢复按钮先修改表单，点击保存后才生效。

设置按账号和作品保存在 MySQL，跨浏览器可读取。新会话由服务端冻结实际指令、来源范围、版本及哈希，参与规划、生成和检查；后续保存设置不会改变已有会话，草稿分支继续沿用原任务指令。作者输入只约束表达与协作方式，不授予工具或数据权限，不覆盖阶段所需的 JSON 格式。剧情资料仍放在剧情笔记和故事资料库；原文风输入框用于本次补充要求。

已有环境升级执行 `docs/sql/writing-assistant-settings.sql`，然后重启 AI 服务并刷新作者端即可；完整新环境迁移仍按下文执行。新表包含在完整扩展 SQL 内，重复执行使用 `CREATE TABLE IF NOT EXISTS`。

### 样文与 Skill

粘贴有权使用的样文，确认费用后提交分析。结果是待确认文风档案，作者检查六类表达偏好及逐字出处后确认，再供写作任务选择。样文剧情和人物不进入正常生成上下文；提取的表达偏好不等于模型已掌握某位作者的写作能力。

个人 Skill 支持新增、编辑、版本历史、停用和删除，可设为本书或自己全部作品可用，每次最多选择两个。导入支持 UTF-8 `SKILL.md` 或文本 ZIP，预览后保存为待确认状态；支持简单的 `name`、`description` 元信息，也可提供 `id`、`version`。不支持任意 YAML、脚本或自动下载。包大小、文件数、路径及展开内容均受限，包内引用只能读取允许的文本。规则不能授予工具或资料权限。任务冻结规则版本；停用、删除和权限变化会阻止后续使用。

### 自动同步与累计摘要

作品级自动处理默认关闭。开启向量或摘要前须确认 API 费用；纯关键词索引不调用向量模型。启用后用「同步已有章节」补建旧资料，之后章节正文、状态、标题、顺序和删除通过事务事件异步处理。不要把异步处理理解为保存后立刻完成。

同一作品串行处理，租约与心跳防止旧 Worker 提交。相同来源版本、正文指纹及模型配置复用索引回执和摘要；显式重建可以重新调用 API。付费步骤失败或执行进程失联后进入待人工重试状态，避免后台重复付费。修复原因后在事件列表重试。

长章节分段读取，逐章摘要保留原文引用、版本、哈希与读取范围，再按章节顺序生成累计摘要。写当前章只加载当前章之前且来源仍有效的累计结果；修改前文会使后续累计结果失效。摘要是未核实的模型整理，不替代正文证据，更不把未来剧情笔记当成既成事实。

后台默认单次最多 30 次派生模型调用、40 万预留 Token、10 分钟，累计压缩每轮最多新增 20 个检查点。达到限制保留已完成结果，需作者检查后继续。限额是保护上限，不是预计费用。

### 草稿分支与合并

草稿版本窗口支持比较、命名分支、继续生成和选择历史版本；修订保存父版本与来源快照，最多展示 100 项。首次从旧任务分支也会归档现有草稿。任务记录按现有 30 天策略清理，不是永久版本仓库。

普通采纳仍要求来源一致。作者同时修改当前正文时，可预览三方合并：基准正文、当前正文、候选修改。独立修改可合并；重叠修改、重复锚点或差异过大交给作者解决，不静默覆盖。提交再校验当前版本，冲突解决内容须显式确认。撤销恢复本次合并之前的正文；撤销后又编辑或并发修改时仍须经过版本检查。

### MCP Client

在作品扩展页配置公开 HTTPS 443 地址及加密保存的 Bearer 令牌，发现工具后逐项授权只读工具。聊天框底部「工具」按连接分组显示具体工具，作者勾选本会话需要的工具，并允许外部查询；最多两个连接，每个连接最多八个工具。未获连接授权的工具不能启用。只读提示是远端声明，不保证服务实际行为；外部输出始终作为未核实参考。

工具选择支持当前会话随开随关，不需要新会话，运行中也可切换；通过 `PUT /api/ai/writing/tasks/{id}/tools` 保存独立的 `toolsVersion`，并写入 `tools_changed` 事件。后台每次规划、检查的模型请求都刷新可用目录，实际外部调用再次读取当前选择，在初始化后、调用前与结果返回后核验。关闭后拒绝后续调用，晚到结果不提供给模型；已经发出的远程请求无法撤回，可能已经计费。开启后在下一次可使用工具的模型调用中生效，不重启或重放当前生成。终止或采纳事务中的任务不能修改工具范围。多个窗口修改冲突时要求重新加载，不能覆盖较新的选择。

资料、文风和助手自定义指令仍沿用原有快照规则；仅 MCP 工具选择实时更新。后台输出写入与工具变更都锁定任务行后更新，避免旧输出覆盖新的工具开关。本次增量不新增数据库表，升级后重启 AI 服务、刷新作者页面即可。

当前支持 Streamable HTTP 的 JSON/SSE、初始化和会话头；不支持 STDIO、启动外部程序或 OAuth 授权向导。拒绝私网地址和重定向，校验所有 DNS 结果、固定连接 IP，保留 TLS 主机名检查。每任务连接数和调用轮次有限，参数和响应受限，调用失败不自动重放。审计保留作品、工具、参数指纹、耗时与状态，不存令牌和正文。

## 删除与备份恢复

章节、作品、故事资料、样文或个人 Skill 删除后，权限及来源校验先阻止后续读取，后台再清理相关索引、摘要、派生文风、任务快照、修订、事件与采纳快照。清理按原作者及作品限定，不能删除另一作者的作品。删除资料不会撤回已经写进正式章节的作者正文，也无法撤回已发送给外部供应商的请求。

无正文删除账本每 30 秒写入独立文件，默认 `./data/writing-deletions.ndjson`，通过 `novel.ai.writing.deletion-journal` 配置。应使用独立持久卷，不能随旧 MySQL 备份一起回滚。管理员可调用 `POST /api/admin/ai/writing/deletions/flush` 刷盘；恢复数据库后保持维护状态，调用 `POST /api/admin/ai/writing/deletions/replay`，请求带 `confirmRestoreCleanup: true`，待清理事件完成并核验索引后开放服务。账本超过 10 MB 或 10000 项需运维归档处理，不能无限增长。

如果数据库与删除账本同时恢复到删除之前，系统没有依据知道之后发生过哪些删除，不能承诺自动清除这些历史副本。删除账本与备份恢复演练须作为部署运维的一部分。

## 部署与验证边界

当前开发库已执行扩展迁移。其他环境按基础写作表、故事资料表、`docs/sql/writing-agent-extensions.sql`、`docs/sql/writing-change-triggers.sql` 的顺序迁移；使用 `docs/tools/ApplyWritingMigration.java` 处理重复执行及中间版本兼容，事件时间必须为 UTC。迁移包括 14 张扩展表（含新增助手设置）、7 个触发器及采纳记录的作品归属字段。

先 clean 构建，再部署并重启 `novel-content`、`novel-search`、`novel-ai`，刷新作者端。仅升级助手自定义指令时，执行其增量迁移并重启 `novel-ai` 即可。本次没有重启正在运行的 IDEA 服务。

最终针对改动的 48 项测试全部通过，包含真实隔离 MySQL 的租约、权限、去重、删除及合并回归；此前写作回归与真实 ES 私有索引测试通过，作者端生产构建通过。MCP 使用假传输和协议样本验证，没有实际连接第三方供应商；没有调用真实付费模型评判文学质量，也未进行浏览器视觉与操作验收。
