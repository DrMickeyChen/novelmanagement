# 找书推荐与多轮引用回归（2026-10-14）

## 修复内容

真实模型评测发现：“推荐几本小说”搜索到20本候选后仍询问题材，导致同组的“换一批”没有可替换作品。

提示词明确：泛化推荐也是有效找书请求，允许使用空条件搜索，不能因未指定分类就放弃候选。仅打招呼仍应询问需求。

模型已经成功搜索、候选存在、没有任何软偏好且最终返回空推荐时，服务端按候选顺序补查最多20本实时详情，再选最多5本，继续执行最终可见性与硬条件校验。补查计入工具次数与执行轨迹，遵守现有超时与工具预算。详情失效、作品下架、服务错误不会被伪装为成功推荐；有软偏好时不触发此补救，尤其不能跳过必要偏好的证据判断。

最终卡片顺序按提议 ID 顺序组装，而不是详情服务返回顺序。下一轮 lastRecommendations.position 与实际卡片一致；空追问保留最近一次展示的作品，明确新话题仍清空旧条件。

## 自动化验证

`BookFinderAgentTest` 连续执行三个真实 Agent.run 调用：首批1～5本、换批6～10本、类似第四本。第三轮先查询上轮第四张卡片（第9本测试作品）的详情，再搜索、查详情、返回第11本，检查三轮条件、排除列表与会话提交。详情服务故意倒序返回，搜索服务故意返回已推荐作品，验证服务端顺序与去重控制。

其他新增测试覆盖：空推荐补救及日志、必要偏好不能被补救绕过、空搜索和问候不编造推荐、补救后的作品仍须通过最终可见性校验。模型、搜索和内容服务在这些测试中使用测试替身，不代表真实模型的语义推荐准确率。

## 真实模型复测

第四轮报告（97e44e1e-7bec-4cc9-a322-042568021549）8/9通过，剩余相似题把推断的“智谋”放入keyword硬过滤而搜空。新增保护将有效序号续问中用户未提及的新关键词转成可选软偏好，保留用户明确关键词及既有条件，重试也不重新加入该过滤。有效相似请求已找到候选但模型仅因可选风格不确定而返回空时，可返回实时校验后的候选卡片，风格判断仍为UNKNOWN，不声称已证明相似；任何必要偏好仍禁止此补救。所有最终空推荐统一needsClarification=true。

未知工具参数错误会列出字段名和允许字段，方便模型纠正；最终JSON结构错误会逐项指出必需字段和类型，修正仍只有一次，不自动补造推荐ID或引用。回归新增关键词转软偏好、显式关键词保留、空结果状态、修正提示字段和可选相似候选未知状态测试。

第三轮真实报告（276ded32-25ff-4c2d-982a-433df2a4d0b9）暴露补救逻辑会覆盖无效序号追问、相似推荐自动加完结限制、正文检索漏查候选详情、最终格式修正缺少原错误回答。后续修复：

- Java 在模型调用前定位阿拉伯数字/中文序号，序号不存在直接追问，模型/工具调用均为0，不触发空推荐补救；保留上一批卡片。
- 有效序号对应的作品作为 referencedBook 放入模型上下文。用户仅要求相似时，忽略模型新传的完结和字数参数，保留已有用户条件；本轮明确说完结、连载或字数时仍可更新。
- searchBookEvidence 校验候选ID后，自动补查缺失详情，只有可见候选才进入正文检索。补查计入工具调用预算与轨迹，不允许任意ID；失效候选不能被解释为未建知识库。
- 正文工具参数失败且没有成功执行正文核对时，空推荐回答由服务端说明核对未执行，避免模型编造“全部未构建”。
- 格式修正输入加入本轮实际错误输出（内部使用，不记录原文），轨迹记录 JSON_INVALID/SCHEMA_INVALID、长度和 finishReason，不猜测失败是否由Token截断造成。

新增回归测试覆盖上述边界，并继续执行已有三轮换批/引用与权限、证据、MCP测试。依旧使用测试替身，不代表真实模型语义准确率。
