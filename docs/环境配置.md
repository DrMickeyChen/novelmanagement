# 开发环境配置指南（Ubuntu 22.04 虚拟机）

> **一步一步来**，每一步都说清楚在干什么、为什么这么做、怎么确认成功。
>
> 目标机器：Ubuntu 22.04 ｜ 4 核 ｜ 8G 内存 ｜ 60G 磁盘 ｜ IP `192.168.127.137`（VMware NAT）
>
> 全部配完约 **30 分钟**，其中大半是等下载。版本 v2.0 ｜ 2026-09-19

## 总览：一共要装六个中间件

先知道自己在装什么。这六个东西是后面写代码时要用到的：

| 中间件 | 干什么用的 | 端口 | 什么时候用得上 |
|---|---|---|---|
| **MySQL 8** | 业务主库，存小说、章节、用户 | 3306 | 第一期就要 |
| **Redis 7** | 缓存、阅读量计数、排行榜、幂等去重 | 6379 | 第一期就要 |
| **Nacos** | 注册中心 + 配置中心（微服务才需要） | 8848 / 9848 / 9849 | 第二期 |
| **RocketMQ** | 消息队列，削峰、解耦、异步审核 | 9876 / 10911 | 第二期 |
| **Elasticsearch** | 全文搜索（按书名、作者搜） | 9200 | 做搜索功能时 |
| **Sentinel** | 限流熔断（可选，第三期） | 8858 | 第三期 |

六个都用 Docker 装 —— **不用一个个去编译安装，一条命令全部拉起**，这是 Docker 最大的价值。

### 配置顺序

```
第 0 步  拿镜像加速地址      （在 Windows 浏览器上做，3 分钟）
第 1 步  换 apt 源           ┐

```

## 第 0 步：拿一个镜像加速地址

**在 Windows 的浏览器上做，不是在虚拟机里。**

国内直连 Docker Hub 基本拉不动镜像，必须先配一个加速器。

1. 打开 https://cr.console.aliyun.com/cn-hangzhou/instances/mirrors
2. 左侧菜单「镜像工具」→「镜像加速器」
3. 复制那个形如 `https://xxxxxx.mirror.aliyuncs.com` 的地址，**先记在记事本里**，第 3 步要用
> **为什么是阿里云？** 2024 年以后，国内公开的镜像站（中科大、网易、Docker 中国等）基本全关停了。阿里云容器镜像服务个人版是免费的，只是需要你登录拿一个专属地址。**别去网上抄别人博客里的地址**，抄了也是白配。

**✅ 确认**：记事本里有了一个 `https://` 开头、`.mirror.aliyuncs.com` 结尾的地址。

## 第 1 步：换 apt 源

**在虚拟机终端里操作。** 后面的命令都在虚拟机里跑，只有特别说明的才回 Windows。

Ubuntu 默认的软件源在国外，装东西慢到怀疑人生。换成阿里云的。

```bash
# 先备份原文件，改坏了能还原
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak

# 把两个国外地址替换成阿里云
sudo sed -i 's|http://archive.ubuntu.com|https://mirrors.aliyun.com|g; s|http://security.ubuntu.com|https://mirrors.aliyun.com|g' /etc/apt/sources.list

# 刷新软件包索引
sudo apt update
```

> **`sed -i` 是什么？** 直接修改文件内容。`s|A|B|g` 意思是"把所有 A 替换成 B"。这里就是把 `archive.ubuntu.com` 全换成 `mirrors.aliyun.com`。备份那一步就是防止替换错了回不去。

**✅ 确认**：`apt update` 输出的地址变成了 `mirrors.aliyun.com`，且没有报错。

## 第 2 步：装 Docker

### 2.1 装依赖和密钥

Ubuntu 自带源里的 `docker.io` 版本太老，所以用 Docker 官方源装。但官方源在国内慢，**这里用的是阿里云镜像的官方源**（内容一样，速度快）。

```bash
# 装三个工具：证书、下载器、密钥管理
sudo apt install -y ca-certificates curl gnupg

# 建密钥目录
sudo install -m 0755 -d /etc/apt/keyrings

# 导入 Docker 官方的 GPG 签名密钥（用来验证软件包没被篡改）
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg \
  | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# 把 Docker 的软件源加进 apt 列表
# $(. /etc/os-release && echo $VERSION_CODENAME) 会自动取出系统代号 —— 22.04 是 jammy
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
```

> **GPG 密钥是干什么的？** 软件源相当于一个"应用商店"，密钥用来验证你下载的包确实来自 Docker 官方、中途没被人改过。不加这一步 apt 会拒绝安装。

### 2.2 装 Docker

```bash
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

装了四个东西：

| 包 | 作用 |
|---|---|
| `docker-ce` | Docker 引擎本体 |
| `docker-ce-cli` | `docker` 命令行工具 |
| `containerd.io` | 底层容器运行时 |
| `docker-compose-plugin` | `docker compose` 命令（★ 注意是插件形式，不再是独立的 `docker-compose`） |

### 2.3 免 sudo + 开机自启

```bash
# 把你的用户加进 docker 组（否则每条 docker 命令都要 sudo）
sudo usermod -aG docker $USER

# 让 Docker 开机自启，现在立刻启动
sudo systemctl enable --now docker

# 让用户组变更在当前终端生效
newgrp docker
```

> **为什么需要这一步？** Docker 的守护进程以 root 运行，普通用户默认没权限跟它说话。加进 `docker` 组相当于给了你这个权限。
>
> ⚠️ **加进 docker 组等于给了 root 权限**（容器可以挂载宿主机文件系统）。开发机上没问题，生产环境要注意。

### 2.4 验证

```bash
docker version
docker compose version
```

**✅ 确认**：两条命令都输出了版本号，没报 "command not found"。

> 如果报 `permission denied`，说明用户组还没生效 —— 关掉终端重新登录一次虚拟机。

## 第 3 步：配镜像加速器

把第 0 步拿到的地址填进去。

```bash
sudo mkdir -p /etc/docker

sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": ["https://这里换成你的专属地址.mirror.aliyuncs.com"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "50m", "max-file": "3" }
}
EOF

sudo systemctl daemon-reload
sudo systemctl restart docker
```

**★ 把 `这里换成你的专属地址` 那段替换成第 0 步复制的真实地址再执行。**

> **`daemon.json` 里另外两项是什么？**
> `log-driver` + `log-opts` 是在限制日志文件大小。不配的话，容器日志会无限增长，几个月后能把磁盘撑爆 —— 这是 Docker 的一条经典运维经验。

**✅ 确认**：

```bash
docker info | grep -A2 "Registry Mirrors"
```

能看到你填的地址就对了。

## 第 4 步：调系统参数

**这一步是 Elasticsearch 的硬性要求。** 不改的话 ES 容器起来就退出，日志里写 `max virtual memory areas vm.max_map_count [65530] is too low`。

```bash
# 临时生效，马上能用
sudo sysctl -w vm.max_map_count=262144

# 写进配置文件，重启也不丢
echo "vm.max_map_count=262144" | sudo tee -a /etc/sysctl.conf
echo "fs.file-max=655360"      | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

> **这两个参数是什么？**
>
> - `vm.max_map_count` —— 一个进程最多能创建多少块内存映射。ES 用 Lucene 建索引，每个索引段都要映射文件，默认的 65530 不够用。**这是 ES 最经典的部署坑。**
> - `fs.file-max` —— 系统级最大文件句柄数。ES 和 RocketMQ 都会大量读写文件，调大防止 "too many open files"。

**✅ 确认**：

```bash
cat /proc/sys/vm/max_map_count
```

输出 `262144` 就对了。

## 第 5 步：加 4G swap

**8G 内存跑这套中间件（约吃 5G），swap 是安全气囊。**

```bash
# 先看看现在有没有
free -h

# 创建一个 4G 的交换文件
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile          # 只有 root 能读写，安全要求
sudo mkswap /swapfile             # 格式化成 swap 格式
sudo swapon /swapfile             # 启用

# 写进 fstab，重启后自动挂载
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

> **swap 是什么？** 内存不够时，把暂时不用的内存页挪到磁盘上，腾出物理内存。慢，但总比被 OOM Killer 杀掉进程强。
>
> **为什么必须做？** 不配的话，内存冲上去的瞬间，Linux 的 OOM Killer 会**随机杀一个容器** —— 通常是 ES 或 MySQL，而且杀谁不确定。症状是"用着用着某个服务没了但看不出原因"，很难排查。有了 swap，最多是变慢，不会突然死。

**✅ 确认**：

```bash
free -h
```

`Swap:` 那一行应该是 `4.0Gi`。

## 第 7 步：改两处配置

### 7.1 生成 `.env`

```bash
cd ~/novel-docker
cp .env.example .env
```

`.env` 里存的是密码和 IP，它被 `.gitignore` 排除，不会提交到 git。

### 7.2 改 IP 和 Nacos 密钥

```bash
nano .env
```

改这两行：

```bash
# 改成虚拟机的 IP
RMQ_BROKER_IP=192.168.127.137

# 换成下面这条命令生成的新值
NACOS_AUTH_TOKEN=生成的token
```

生成新 token：

```bash
openssl rand -base64 32
```

> **Nacos 这个 token 是干什么的？** Nacos 开鉴权后，服务端用它来签名校验请求。**必须是 Base64 编码后至少 32 字节**，所以不能随便写一个字符串。`openssl rand -base64 32` 生成的正合适。
>
> 改完按 `Ctrl+O` 保存，`Ctrl+X` 退出。

### 7.3 改 `broker.conf`（★ 最重要的一处）

```bash
nano broker.conf
```

把 `brokerIP1` 改成同一个 IP：

```
brokerIP1 = 192.168.127.137
```

> ### ★ 这是 RocketMQ 容器化最经典的坑，一定要理解
>
> Broker 启动时会**把自己的地址注册到 NameServer**。客户端先从 NameServer 查到 Broker 的地址，再直接去连它。
>
> 如果不配 `brokerIP1`，Broker 会把自己的**容器内网 IP**（`172.17.0.x`）注册上去。你 Windows 上的客户端拿到这个 IP —— 那是 Docker 内部的虚拟网段，你的电脑根本访问不到，直接报错：
>
> ```
> connect to 172.17.0.3:10911 failed
> ```
>
> 而且这个错误日志很难让人联想到"是容器 IP 的问题"，所以特别浪费时间。**配成宿主机的真实 IP 就对了。**

**✅ 确认**：

```bash
grep -E "RMQ_BROKER_IP" .env
grep -E "brokerIP1" broker.conf
```

两处显示的应该是**同一个 IP**。

## 第 10 步：接到项目里

环境配好之后，后端连过去就是改一下 host。在 Windows 上的 `application.yml` 里：

```yaml
spring:
  datasource:
    url: jdbc:mysql://192.168.127.137:3306/novel?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true

    password: root123456

    redis:
      host: 192.168.127.137
      port: 6379
      password: redis123456

  name-server: 192.168.127.137:9876

把 `schema.sql` 放进 `~/novel-docker/init/` 目录，MySQL 容器**首次启动**时会自动执行。

```

> **「首次」的意思**：只有当 `~/novel-docker/data/mysql/` 是空的时候才会跑。如果库已经建好了你才改 `schema.sql`，得手动执行：
>
> ```bash

## 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `docker: command not found` | 重新登录虚拟机，或 `newgrp docker` |
| `permission denied ... docker.sock` | 用户组没生效，同上 |
| `docker pull` 超时 / `context deadline exceeded` | 加速器没配或配错。检查 `cat /etc/docker/daemon.json`，改完 `sudo systemctl restart docker` |
| ES 容器起来就退出 | `vm.max_map_count` 没生效，回第 4 步 |
| ES 报 `Exit code 137` | 被 OOM 杀了。关掉别的服务，或把 compose 里 `ES_JAVA_OPTS` 改成 `-Xms512m -Xmx512m` |
| Nacos 控制台能开，但客户端连不上 | **9848 端口没映射**，`sudo docker compose ps` 检查 |
| RocketMQ 报 `connect to 172.17.0.x:10911 failed` | `broker.conf` 的 `brokerIP1` 不对，回第 7.3 步 |
| MySQL 报 `Public Key Retrieval is not allowed` | 连接串加 `allowPublicKeyRetrieval=true` |
| Windows 连不上虚拟机 | 虚拟机里 `sudo ufw status` 看防火墙；再确认 VMware 网络模式 |
| 虚拟机重启后 IP 变了 | 见下面附录 |
| 端口被占用 | `sudo ss -tunlp \| grep 3306` 查是谁 |
| scp 报 `Connection refused` | 虚拟机的 ssh 服务没起：`sudo systemctl start ssh` |

## 附录：固定虚拟机 IP

虚拟机 IP 一变，`broker.conf` 和后端配置就全失效了。VMware NAT 的 DHCP 租约通常比较稳定，**可以先不管**，等真遇到了再固定。

> ⚠️ 配错会把自己关在门外。所以**用 `netplan try` 而不是 `netplan apply`** —— 它会在 120 秒后自动回滚，除非你按回车确认。

```bash
# 先查清三样东西
ip addr        # 网卡名（ens33 / ens160 之类）
ip route       # 网关地址（default via ...）
hostname -I    # 当前 IP

sudo nano /etc/netplan/00-installer-config.yaml
```

改成（**网卡名、网关、IP 按上面查到的填**）：

```yaml
network:
  version: 2
  ethernets:
    ens33:
      dhcp4: false
      addresses: [192.168.127.137/24]
      routes:
        - to: default
          via: 192.168.127.2
      nameservers:
        addresses: [223.5.5.5, 8.8.8.8]
```

```bash
sudo netplan try     # 120 秒内新开一个终端 ping 一下，通了再回原终端按回车确认
```

**如果 IP 真的变了**，改两个地方再重启 broker：

```bash
cd ~/novel-docker
nano .env            # 改 RMQ_BROKER_IP
nano broker.conf     # 改 brokerIP1
sudo docker compose restart rmqbroker
```

后端的 `application.yml` 也要跟着改。

## 附录：内存账（8G 机器）

| 服务 | 内存 |
|---|---|
| Elasticsearch | ~1.8G |
| RocketMQ Broker | ~0.7G |
| Nacos | ~0.7G |
| MySQL | ~0.5G |
| RocketMQ NameServer | ~0.3G |
| Redis | ~0.2G |
| Ubuntu + Docker | ~0.8G |
| **合计** | **~5G / 8G** |

还剩 3G 余量，够用但不宽裕。`docs/docker/docker-compose.yml` 里的堆内存是**特意压过**的：

```yaml
Nacos   JVM_XMX: 512m
Broker  JAVA_OPT_EXT: "-Xms512m -Xmx512m -Xmn256m"
ES      ES_JAVA_OPTS: "-Xms1g -Xmx1g"
```

> **别照抄网上教程的值。** 很多教程写 ES `-Xms2g`、RocketMQ Broker 用官方默认的 `-Xmx8g`，在 8G 机器上照抄必 OOM。
