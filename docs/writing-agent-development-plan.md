# 写作 Agent 长期设计与能力路线

更新日期：2026-10-14  
状态：长期设计稿，尚未实施。本文中的工具、接口、数据表和目录均为拟议设计，不代表现有功能已经完成。

> 2026-10-14 评审订正：本文件保留完整能力路线，不再作为首版施工范围。首版以 [写作 Agent MVP 实施规格](writing-agent-mvp-spec.md) 为准。下面原有“首版”、分支、三方合并、外部 Skill 和 MCP 描述若与 MVP 规格冲突，以 MVP 为准；不得按本文件一次性全量开工。状态、预算、接口及验收的首版约束详见 MVP 文档。

## 1. 目标、范围与现状

建设一个在作者控制下，依据大纲、前文和作品规则完成规划、起草、检查与修改的本章写作 Agent。执行过程可恢复，事实判断有出处，正文修改可追踪。

基于现有 `novel-ai`、`novel-content` 和 `author-web` 实现，复用现有聊天模型配置、密钥加密、用量记录、章节编辑器及大纲树。写作 Agent 与找书 Agent 共用基础设施，但独立管理工具、会话、资料权限和检索索引。

### 1.1 已有能力与待修问题

- 已有大纲生成、续写、灵感、选区润色、SSE 输出和人工采纳。
- 已有后端前情摘要接口；本次代码阅读未发现作者端调用入口。
- 已有服务端大纲和摘要上下文组装，但 AI 面板构建请求时只保留 `prompt/context`，丢失工作台准备的作品、章节和节点 ID，需要先修复。
- 写作目前走原有模型调用链，尚未使用写作专用的 LangChain4j 工具执行流程。

### 1.2 首版范围

- 本章目标与约束、有效大纲校验、情节方案确认。
- 前文回顾、相关原文检索、当前编辑内容快照。
- 按类型、文风、格式生成草稿，进行检查和多轮修改。
- 多草稿版本、分支对比、局部或全部采纳、撤销。
- 内置 Skill 选择、个人 Skill 编辑、兼容外部 Skill 导入。
- 任务持久化、失败恢复、权限隔离、逐阶段评测。

MCP Client 作为后续扩展阶段，优先接入外部作者笔记和资料检索。整本小说自动创作、多人实时协同编辑、任意外部脚本执行不属于首版范围。

## 2. 不可绕过的业务规则

| 规则 | 实施要求 |
| --- | --- |
| 正式生成必须先有大纲 | 本章大纲至少包含主要事件、章节目标和结尾安排，经过作者确认；不能只凭非空标题通过 |
| 作者决定正文变更 | 模型只创建计划、草稿和修改建议，采纳、回滚、发布由作者触发 |
| 固定输入版本 | 每次执行绑定正文、大纲、配置、Skill 和资料版本 |
| 私有资料隔离 | 每次读取校验作者、作品和资料范围，身份由服务端决定 |
| 前文时间范围明确 | 默认只把当前章之前的正文作为已发生事件；未来大纲只能作为创作意图 |
| 已有事实与新建议分开 | 新设定未经作者确认不能进入正式设定库 |
| 失败保留工作 | 中断、超时、重试不覆盖正文，不拼接不同生成尝试 |

允许作者先讨论、写片段、保存灵感或让助手辅助补大纲；没有确认大纲时，不进入正式章节生成。是否允许未来大纲参与规划由作者显式选择，必须保持与前文事实的来源区分。

## 3. 架构与职责

```text
Vue 作者工作台
  ├─ 创作配置 / 作者资料 / Skills / 外部工具连接
  └─ 计划确认 / 草稿版本 / 检查 / 对比 / 采纳
             ↓
写作任务 API 与任务编排器
  ├─ 权限、状态、版本、确认、预算、重试、审计
  ├─ LangChain4j：模型交互与工具调用
  ├─ Java Tools / Skill 加载
  └─ MCP Client：已授权外部工具
             ↓
novel-content：大纲、章节、正文版本与归属校验
MySQL：持久化任务、计划、草稿、证据、事件与审计
Elasticsearch：作者私有正文及资料检索
Redis：缓存、短期锁、限流；不承担恢复的唯一依据
```

LangChain4j 负责模型与工具交互；Java 业务编排器决定阶段、权限、确认和写入条件。先验证当前依赖版本的流式工具调用、取消、结构化输出及失败传播，不能仅依据框架名称承诺恢复能力。

## 4. 作品创作配置

作品类型、文风和格式分别配置，并维护版本。

| 配置 | 示例 |
| --- | --- |
| 类型 | 修仙、悬疑、轻小说，允许组合 |
| 叙述 | 人称、视角、时态、视角切换规则 |
| 文风 | 克制、短句、动作表达、少解释、禁用表达 |
| 格式 | 对话 `“……”` 或 `「……」`、独白符号、分段及标题 |
| 固定约束 | 不改变修炼体系、不提前揭露身份 |
| 默认 Skill | 本书允许使用的创作策略 |

提供格式预览。确定性的符号和结构规则由程序检查；语气、节奏等采用模型检查和人工评价。

本次要求可以调整篇幅、情绪等参数，但不能静默覆盖作者确认的固定设定。冲突时进入等待输入状态，由作者修订或明确授权。配置变更生成新版本，不追溯覆盖已执行任务。

## 5. 作者知识库、前文回顾与文风档案

### 5.1 资料用途隔离

| 类型 | 地位 | 使用入口 |
| --- | --- | --- |
| 已确认设定 | 本书约束 | 设定检索 |
| 本书正文 | 已发生剧情，受章节范围与版本约束 | 前文检索 |
| 待确认设定、建议 | 候选，不是事实 | 方案讨论 |
| 文风样文 | 表达参考，不导入人物和剧情事实 | 文风分析专用 |
| 外部考据 | 待核对参考 | 外部资料入口 |

资料记录用途、来源、作者、作品范围、确认状态和版本。不能仅依赖提示词隔离。常规事实检索必须排除样文；一般生成优先加载已确认文风档案，补查样文需有本次授权。

### 5.2 三层前文上下文

1. 整体回顾：累计摘要、关键事件、人物状态。
2. 最近衔接：最近章节摘要、前章结尾、当前编辑快照。
3. 相关证据：按本次涉及的人物、物品、事件及疑问检索原文。

摘要保留覆盖章节、来源正文版本、生成版本及过期状态。前文修改后，相关摘要标记过期，并触发可重试更新；不得把过期摘要展示为最新结论。摘要服务于回顾，原文用于核实具体事实。

### 5.3 事实与证据

建议结构：

```text
claimId / statement
kind：确认设定、正文事实、待确认建议、外部参考
sourceId / sourceVersion / chapterId
anchor：段落、字符区间、引用文本、内容哈希
assessment：支持、冲突、待确认、资料不足
verifiedBy：作者或检查过程
```

追踪草稿依赖的关键事实、检查结论和新设定来源，不要求所有创作句子都有出处。引用必须能定位原版本；失效引用标记过期。模型自报百分比不作为准确率或可靠置信度。

### 5.4 样文分析

作者上传 TXT 或粘贴文章 → 分析句式、叙述距离、对话、描写、情绪与节奏 → 给出例证与分析范围 → 生成可编辑文风档案 → 作者确认。

文风档案独立版本化；允许“仅本次调整”与“更新本书规则”。样文删除或更新后标记相关分析来源状态，避免未经提示继续引用已删除材料。

## 6. 状态机与非线性创作

### 6.1 主流程

```text
CREATED → PREPARING → PLANNING → WAITING_PLAN_CONFIRMATION
                                      ↓ 确认计划
                                  GENERATING
                                      ↓
                                   CHECKING
                                      ↓
                                READY_FOR_REVIEW
                                ├─ 修改 / 新分支
                                ├─ 局部或全部采纳
                                └─ 完成或暂存
```

执行阶段可以进入 `WAITING_INPUT`、`FAILED`、`CANCELLED`、`PAUSED`。任务、步骤、尝试分别记录状态；状态转换通过版本条件更新，禁止多个工作进程同时推进同一尝试。

### 6.2 分支规则

| 行为 | 结果 |
| --- | --- |
| 调整计划 | 新建计划版本，旧草稿保留 |
| 修改关键设定 | 标记依赖结果过期，重新准备资料 |
| 选择另一方案 | 新建草稿分支 |
| 跳章 | 新建独立章节任务 |
| 局部修改 | 绑定目标草稿版本，新建修改尝试 |
| 拒绝 | 保存作者可选拒绝原因，用于本任务重写 |

一次确认可授权计划范围内的多轮修改，改变关键事件或固定设定需再次确认。支持批量确认，但需展示具体对象。超时默认暂存或等待，不默认批准和采纳。

## 7. 持久化恢复、取消和幂等

- MySQL 保存任务、步骤、执行尝试、输入快照、已完成结果、事件和错误类型。
- 流式草稿按小批次持久化；持久化失败时中止推进并明确记录，不声称结果已保存。
- SSE 事件携带任务 ID、尝试 ID、递增序号。重连先取任务快照，再补事件；事件过期时重新取快照。
- 浏览器断线不自动取消任务；作者取消单独发请求。
- 取消标记持久化，尽力中断模型和工具；晚到结果不能推进已取消尝试。
- 重试创建新尝试；只复用版本仍有效的步骤结果，不拼接两次输出。
- 未完成草稿明确标注，作者采纳时提示其完整性。
- Worker 使用持久化租约、心跳和递增执行代次；失效 Worker 的提交必须被拒绝。
- 任务提交、结果保存、采纳采用幂等键；Redis 锁仅辅助，数据库条件更新与唯一约束作为最终保证。

任务恢复不等于续接同一次模型流。模型调用失败可重新执行生成步骤，但保留原尝试；无法获知取消后的真实计费量时标记未知。

## 8. 工具与业务操作

### 8.1 模型工具

| 工具 | 职责 |
| --- | --- |
| `getWritingProfile` | 读取类型、文风、格式与约束 |
| `getChapterOutline` | 本章及相关上级大纲 |
| `getStoryRecap` | 前文回顾、覆盖及版本 |
| `getRecentChapters` | 最近前文 |
| `getWritingContext` | 本次编辑快照、目标和约束 |
| `searchNovelEvidence` | 本书前文证据 |
| `searchAuthorKnowledge` | 指定类型的私有资料 |
| `getStyleSamples` | 已授权样文 |
| `checkWritingFormat` | 确定性格式检查 |
| `savePlanProposal` | 保存候选计划 |
| `saveDraftRevision` | 保存候选草稿 |
| `saveCheckReport` | 保存检查结论与证据 |

保存工具只写当前任务候选结果。任务、作者及作品标识由服务端绑定，不接受模型任意切换。每个工具限制参数、输出长度、时间、并发和配额，并区分可重试错误、无结果、权限拒绝及永久失败。

### 8.2 作者业务接口

作者触发确认计划、分支选择、拒绝记录、局部或全部采纳、撤销、设定确认和章节发布。模型不能调用正式正文采纳或发布接口。

候选写入、正式采纳都需事务与审计；涉及跨服务修改时以 content 的版本和幂等记录为准，通过可重试同步或对账补齐 AI 侧状态，不能假设跨服务数据库事务。

### 8.3 权限矩阵

| 操作 | 作者 | 模型 | 管理员 |
| --- | --- | --- | --- |
| 读私有资料 | 本人授权范围 | 当前任务授权范围 | 不因管理身份默认开放正文 |
| 保存计划、草稿 | 本人任务 | 当前任务 | 不代作者创作 |
| 确认计划、采纳正文 | 允许 | 禁止 | 按明确业务权限 |
| 发布 | 现有发布流程 | 禁止 | 现有审核流程 |
| 管理配置 | 个人配置 | 禁止 | 平台配置 |

现有系统无租户概念时使用 `ownerUserId + novelId`；不得把空租户当作共享空间。未来租户扩展必须覆盖查询、索引、缓存、连接和审计。

## 9. 草稿、三方合并与撤销

每次生成绑定基准正文版本及快照、计划、配置、Skill、资料版本，以及目标选区锚点。草稿保留父版本，可形成分支，但首版不建设复杂版本 DAG。

采纳流程：

1. 当前正文未变：校验目标范围后应用。
2. 当前正文已变：比较基准正文、当前正文和候选修改。
3. 无重叠修改且可可靠定位：合并。
4. 重叠修改或锚点歧义：展示冲突，不自动覆盖。
5. 提交时再次校验章节版本，事务内保存新正文版本与幂等记录。

重复采纳只生效一次。撤销是新的可审计操作，同样进行版本和冲突校验；不直接用旧快照覆盖作者后续修改。首版不引入 OT/CRDT。

## 10. Skill 管理

内置 Skill：情节规划、按文风起草、文风分析、一致性检查、局部润色；专项 Skill 可增加悬疑铺垫、战斗场景等。

作者管理个人 Skill，为作品设置默认选择、本次临时选择；Agent 只在允许范围内按需使用，并显示实际使用版本。

Skill 定义名称、描述、适用任务、步骤、工具依赖、输出要求及参考文件。它是平台兼容的版本化任务说明，不是 LangChain4j 自动提供的业务能力。

### 10.1 外部导入

- 首版支持兼容的 `SKILL.md` 和 ZIP，不保证任意客户端 Skill 能运行。
- 限制文件数、压缩与解压大小；拒绝路径越界、链接和可执行内容。
- 使用受限解析器，禁止动态求值；参考文件只能访问导入包内允许资源。
- 预览内容、工具依赖和不支持项，作者明确启用。
- 保存来源、哈希和版本；更新需要重新确认，不自动跟随远程内容。
- Skill 权限只能来自平台授权，不能从文本获得。
- 指令不能覆盖权限、大纲前提、作者确认和正文采纳规则。

来源签名可后续加入，但签名不代表内容可信。注入检测仅作辅助，执行安全依赖工具权限、参数校验和资料边界。

## 11. MCP Client

第一批接入作者笔记和资料检索、网页读取，优先支持 Streamable HTTP。工具名字与参数以实际服务发现结果为准，不预设所有服务一致。

作者端提供连接配置、认证、测试连接、工具预览、工具授权、个人/作品/任务启用范围和调用记录。

- 每个连接绑定作者；令牌分别加密保存，OAuth 按服务能力支持。
- Skill 可声明依赖，但不能自动添加连接、安装程序或取得权限。
- 工具列表或权限要求改变后重新确认。
- 限制协议、域名、解析后的地址、重定向及每次连接目标；防范 DNS 重绑定和 SSRF。
- 默认禁止内部、回环及元数据地址；本地自托管例外由管理员明确允许，并维持同等网络边界。
- 设置超时、并发、结果大小、熔断和审计。
- 发送私有内容需符合作者授权的最小范围；记录披露范围，不记录明文凭据。
- 外部内容作为不可信参考，不能获得系统指令地位。

MCP 失败时保留本地工作；必要资料缺失进入等待，非必要资料缺失允许作者选择继续。

## 12. 检索隔离与索引更新

- 作者私有索引与读者找书索引独立命名、访问路径和服务权限。
- 文档强制包含作者、作品、用途、版本、状态及章节范围字段。
- BM25 和向量召回阶段都带权限条件，禁止先召回私有结果再在 Java 过滤。
- 对检索结果在返回模型前再次校验版本与权限；缓存键绑定身份和授权版本。
- Embedding、Rerank 调用前校验资料范围，并记录外部披露与模型版本。
- 原文变更先在权威数据源更新版本/状态；检索结果需核对该状态，不能等 ES 同步后才限制旧资料。
- 通过事务事件记录、可重试消费及定期对账更新摘要和索引，防止仅靠一次 MQ 投递丢更新。
- 删除后立即拒绝逻辑访问，再完成索引、附件和派生资料清理。

模型、维度及分块规则变化时建立新索引、验证后切换别名并保留回退窗口。Rerank 变化通常不必重建向量，但需重新评测。

## 13. 数据实体、存储与目录

拟议实体名称，实施时结合现有表规范调整：

| 实体 | 内容 |
| --- | --- |
| `writing_profile` | 创作配置版本 |
| `author_knowledge_document` | 私有资料元数据及用途 |
| `style_profile` | 文风分析及确认版本 |
| `story_recap` | 摘要、覆盖和来源版本 |
| `writing_task / step / attempt` | 执行状态、租约、预算和恢复 |
| `writing_plan` | 计划及确认记录 |
| `writing_draft / revision` | 草稿版本及父版本 |
| `writing_claim / evidence` | 事实及来源锚点 |
| `writing_adoption` | 采纳、版本及幂等 |
| `author_skill / skill_version` | Skill 版本 |
| `mcp_connection / tool_grant` | 连接和授权 |
| `writing_event / tool_audit` | 事件与审计 |

MySQL 保存任务与正文快照等持久状态；ES 保存检索片段和向量；Redis 保存缓存、短期锁及限流。附件通过受控文件接口保存，不能直接暴露私有文件路径，预留对象存储适配。

保留期限在上线前定值：正文采纳历史、候选草稿、事件、审计、附件分别配置。不得默认自动删除作者正式作品。删除操作覆盖派生资料，备份保留和恢复后的再删除规则也需说明。

建议目录：

  api/ application/ domain/ tools/ context/ evaluation/

数据库使用兼容性增量迁移和功能开关；回滚应用不删除作者数据。新服务路径未启用时保持原功能可用，不能静默在新旧任务中混用。

## 14. 预算与降级

阶段零测量后设置可配置的任务、步骤和工具超时；独立限制输入长度、检索量、调用轮数、输出 Token、并发和费用。使用软/硬预算，接近软上限时停止扩大检索，达到硬上限保存结果并结束尝试。

| 故障 | 处理 |
| --- | --- |
| Rerank 失败 | 使用融合排序，标记降级 |
| Embedding 失败 | 关键词检索，说明检索范围 |
| ES 失败 | 仅使用固定大纲与最近前文，不宣称全面核验 |
| MCP 失败 | 保留本地流程，必要资料缺失则等待 |
| 模型失败 | 保存部分结果及错误，按尝试重试 |
| Redis 失败 | 不绕过权限、配额和并发保证；必要时拒绝新执行 |
| MySQL 失败 | 停止持久化依赖操作，不声称保存或采纳成功 |

自动重试仅用于明确可重试且幂等的操作，受次数和预算约束。聊天、Embedding、Rerank 用量分开记录，价格规则版本化；无法获取的用量或费用标记未知，不填零。

## 15. 前端体验

- 资料与规则：大纲、目标、约束、配置、Skill、工具授权。
- 计划：多方案、调整、确认、变更影响。
- 草稿：流式输出、版本分支、对比、局部修改。
- 检查：冲突、待确认、资料不足、来源定位。
- 任务：当前阶段、暂停、取消、恢复、重试。
- 采纳：选区预览、合并冲突、撤销。

默认展示资料来源和实际 Skill，不把内部工具参数放进日常创作流程。部分输出、过期资料、降级检索和检查覆盖范围必须清楚显示。

## 16. 验收与评测

### 16.1 发布门槛

以下固定功能用例必须全部通过；这表示回归集通过，不代表对所有未知情况的绝对保证。

| 编号 | 场景 | 断言 |
| --- | --- | --- |
| AUTH-01 | 使用其他作者作品、章节、资料 ID | 拒绝，模型/外部服务未收到该资料 |
| AUTH-02 | 作品与章节或节点归属不一致 | 拒绝，不执行生成 |
| OUTLINE-01 | 大纲缺失、只有标题、未确认 | 不能进入正式生成，可补充方案 |
| CONTEXT-01 | 工作台发起不同写作场景 | ID 正确保留，服务端获取对应资料 |
| SOURCE-01 | 样文包含其他人物和世界观 | 不进入剧情事实通道；人工检查输出污染 |
| VERSION-01 | 前文、设定或计划修改 | 识别过期版本，不能默默继续当作最新依据 |
| STREAM-01 | 生成时断线并重连 | 恢复已保存结果，不重复启动或混合尝试 |
| WORKER-01 | 工作进程失效，旧 Worker 晚到提交 | 新尝试可恢复，旧提交被拒绝 |
| CANCEL-01 | 生成或工具执行时取消 | 保存取消状态，晚到结果不推进任务 |
| RETRY-01 | 模型失败后重试 | 新尝试，旧部分结果保留，预算累计明确 |
| ADOPT-01 | 重复采纳请求 | 正文只修改一次 |
| MERGE-01 | 同一区间并发修改、重复文本锚点 | 显示冲突或拒绝定位，不静默覆盖 |
| UNDO-01 | 采纳后再次编辑再撤销 | 检测冲突，不覆盖后续修改 |
| SKILL-01 | 越界路径、解压炸弹、脚本或越权指令 | 导入/执行受限，不能提升权限 |
| MCP-01 | 内部地址、重定向、工具注入、授权撤销 | 访问受限，未授权数据不外发 |
| DELETE-01 | ES 尚未同步时删除私有资料 | 查询与模型输入已排除被删除资料 |

### 16.2 质量指标及人工评分

- 引用准确率：被核验引用中，可定位且确实支持对应结论的比例；同时记录无引用结论。
- 事实错误率：草稿中可核验陈述的错误比例，区分模型错误和资料本身冲突。
- 冲突检测：固定标注集上的查准率、召回率及误报。
- 创作评分：连贯性、人物一致性、大纲目标完成度、文风符合度，各使用 1～5 分量表；3 分为基本满足、5 分为充分满足且无明显问题，无法判断单列。
- 计划采纳率、拒绝原因、人工修改距离：作为使用反馈，不单独证明准确性。
- 局部采纳成功率：目标位置正确、无非目标改动、通过作者或自动校验。
- 恢复成功率：故障注入任务中，能够恢复到明确状态且不重复写入的比例。

真实模型基准使用固定样本、来源版本、人工标注及重复运行。质量/延迟/成本目标需在阶段零、基准数据阶段定值并固化到验收表；不能无依据承诺准确率。阈值未确认前不宣称达到生产 SLO。

### 16.3 性能、成本、观测与证明

记录首个进度、首个草稿文本、总耗时 P50/P95，步骤/工具耗时，模型用量、费用、错误和降级。报告保留任务、数据/配置/Skill/模型版本、工具轨迹、自动断言及人工结果，敏感正文按权限访问。

告警覆盖任务长期停滞、失败率、索引积压、配额异常和成本异常。模型、提示词、Skill 或检索配置变更后跑固定回归，观察质量与费用漂移。

协议测试不等于真实模型质量；Mock 不作为文风或事实能力证明。

## 18. 首版完成定义

作者在有效大纲基础上，能调用授权资料形成可确认计划，按选定文风和格式生成草稿；能够查看有依据的检查、多轮修改、恢复中断任务，并安全采纳或撤销。

交付包括代码、数据库增量脚本、作者端操作说明、回归集、真实模型评测报告及限制清单。外部 MCP 在独立阶段交付，不阻塞本地创作流程；不得把尚未完成的扩展写成已集成能力。
