# 本章写作 Agent：启用与使用

2026-10-14 已扩展故事资料库、分层笔记、手选前文和私有 RAG，具体规则见 [故事资料库与私有上下文](writing-agent-context-library.md)。写作代码已分层，内置 Skill 从文件加载，新增文件与部署方法见 [代码结构与 Skill 文件](writing-agent-architecture.md)。

## 启用

1. 在 MySQL 的 `novel` 数据库执行 `docs/sql/writing-agent-mvp.sql` 和 `docs/sql/writing-story-library.sql`，必须先迁移再启动新版 content。MVP 的 SQL 原文件只执行一次；重复部署可使用 `docs/tools/ApplyWritingMigration.java` 检查并补齐缺失对象。
2. 先重启 `novel-content`、`novel-search`，再重启 `novel-ai`。当前 `dev` 配置默认启用；其他环境默认关闭，需加程序参数 `--novel.ai.writing.enabled=true`（或环境变量 `WRITING_AGENT_ENABLED=true`）。启用不自动调用模型，作者创建任务才启动。
3. 作者端刷新页面，进入作品大纲树的一个已绑定正文的章节。旧标签页保存缺少版本会被拒绝，应刷新。

继续使用现有聊天模型配置和加密 Key，不需要再填一把写作 Key。管理员不限每日次数，但仍受任务 Token、并发和超时上限约束。

## 操作

2026-10-14 已使用可重复迁移工具在开发数据库补齐章节版本列、6 张任务/采纳表及 3 张故事资料/索引任务表，没有修改既有小说正文，也没有重启用户正在运行的服务。再次部署先检查迁移状态，不重复直接执行 ALTER。

填写并保存本章剧情笔记作为大纲。在正文框选择要替换的区间，或把光标放到插入位置。在右侧助手输入本章目标并发送；约束、类型、视角和文风收在“写作设置”中。

聊天输入框底部的“Skill”按钮弹出可多选列表；已选项以标签展示，点击标签关闭按钮或“清空选择”可移除。新建任务、确认计划、修改草稿和失败重试均提交当前 Skill 选择，作用于下一次模型执行。生成过程中暂不能切换；已生成的草稿不会自动重写，需提交修改要求。当前提供“克制叙述”“对话驱动”两个内置 Skill。

查看前文回顾和覆盖范围，在表单中调整本章安排、主要事件和结尾，一次确认后开始生成。计划缺少必要信息时补充大纲并新建任务。

草稿完整生成后查看检查结果，可以继续描述修改要求。选中草稿中的文字可局部采纳；“采纳整份草稿”仍只替换最初正文选区，不是覆盖整章。未完成检查需要作者显式确认。

助手右上角提供“新会话”和“历史”。新会话打开空白输入区，不调用模型、不删除或取消旧任务；发送目标后才创建独立任务。历史列表显示本章最近 30 天最多 10 条记录的目标、状态和创建时间，点击恢复计划、草稿及其操作状态。未完成会话可以继续，已采纳或取消的会话可查看结果；切换会话不直接修改正文。正在生成的旧会话仍在后台执行，可从历史返回；同一作者的模型任务按现有调度规则排队，最多保留 5 个未结束任务。

断线只恢复订阅，不重启模型请求。取消和超时保留部分结果，但首版不允许采纳未完成草稿。

采纳前作者有任何正文或标题修改都会触发版本冲突，系统保留正文与草稿，提供复制或新建任务的处理方式，不自动合并。撤销只支持没有后续编辑、未重新提交审核或发布且记录未过期的采纳。

## 已实现范围与限制

- LangChain4j AI Services 组织规划/检查及只读 Java 工具；正文使用 LangChain4j 流式模型接口。
- 新任务读取章、卷、全书剧情笔记与前三章正文，普通长度章节按预算读取全文，长章明确显示分段范围；支持额外手选及私有正文 RAG。旧任务保留原读取范围。
- 作者可选“克制叙述”“对话驱动”内置 Skill，文件位于 `novel-ai/src/main/resources/writing/skills/*/SKILL.md`，前端选项由后端提供，新任务保存实际规则与文件版本。外部 Skill、样文分析和 MCP 未包含。
- 文风、题材和格式的默认表单设置保存在当前浏览器，每个任务的实际输入持久化在 MySQL；不是跨设备作品配置中心。
- “资料”按钮支持额外指定更早章节、设定和后台构建私有索引，作品工作区提供可编辑故事资料库。
- 状态、尝试及事件在 MySQL 保存；事件以已提交完整任务快照通知，客户端替换状态，不拼接不同尝试输出。首版未采用增量 offset 协议。
- 默认每任务最多 10 次模型、12 次工具调用；软预算 160000、硬预算 220000 Token，输入估算上限 48000，可通过配置调低。预留在取得真实用量后结算；向量和重排费用另计。估算不是供应商精确分词。
- 运行记录可导出 JSON，但它不是自动质量评测报告。固定质量集在 `docs/evals/writing-agent/cases.json`，真实模型质量和人工评分需另行执行。
- 首版存储使用 UUID 字符串和任务 JSON，不按长期设计创建全部领域表。
- 内置格式检查可发现对话符号混用；原文引用定位可以验证，但模型对原文的解释仍需作者核对。

## 测试

后端写作测试使用本地假模型接口及 UUID 命名的独立 MySQL 测试库，不修改小说业务数据。通过 `-Dwriting.mysql=true` 启用数据库测试，需要 `WRITING_TEST_DB_PASSWORD` 环境变量。Java 24 的 Mockito 兼容测试加 `-Dnet.bytebuddy.experimental=true`；应用仍按 Java 21 编译。

报告应区分结构/协议测试、实际 MySQL 并发测试、真实供应商质量评测、人工浏览器验证。未执行的项不得写成通过。

## 保留与运维

任务/草稿 30 天，事件 7 天，等待任务 7 天过期。恢复任务使用数据库租约；进程异常后的模型执行不会自动再计费，需手动重试。

备份恢复后私有数据清理与删除账本的完整运维管道仍需后续完善；现有首版依靠归属校验阻止访问已删除作品的任务，不承诺备份删除传播已经完成。不能据此宣称符合完整生产数据治理要求。

关闭写作开关停止新任务调度，已有正文不回滚。普通章节版本保护继续启用，避免旧客户端绕过保护。
