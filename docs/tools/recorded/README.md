# recorded/ —— 真实 DeepSeek 响应的原始字节

**这些是花钱买来的。别删，也别「顺手格式化」—— 格式化会把分片边界改掉，那正是它们的价值。**

## 里面是什么

| 文件 | 是什么 | 谁在用 |
|---|---|---|
| `r1-stream.sse` | 一次真实**流式** `WRITE` 的完整响应字节（303 个 `data:` 帧 + `[DONE]`，87 KB） | `fake-openai.py` 的 `model=fake-replay`（`FAKE_REPLAY` 默认就指向它） |
| `r1-stream.req.json` | 同一次调用的**请求体**（服务端到底把哪段文本发出去了） | 人手看 —— 它是「三段式组装 + 整行移除」的实证 |

| `r2-audit.req.json` | 同一次的请求体 | 同上 |

## 它们买到了什么（两条，都是**假端点永远验不了**的）

1. **`usage` 的真实形状与真阳性对照。** 判据「`ai_usage_log` 的 token 不全为 0」，
   只有一次真实调用能证明 —— 假端点返回的是*我们以为的*形状，用它验等于用假设验假设。
   实测：`{"prompt_tokens":219,"completion_tokens":300,"total_tokens":519,...}`。
   ★ 而且 `usage` **只出现在最后一帧**，那一帧的 `choices` **不是空数组**
   （是 `[{"delta":{"content":""},"finish_reason":"length"}]`）——
   与 OpenAI 协议文档里「usage 帧 choices 为 `[]`」的写法**不同**。见 `docs/E1-AI能力接入.md` 判断 4 的实测订正。
2. **多字节中文没被分片切坏。** 拼回的正文里 **0 个 U+FFFD**。
   这一条假端点同样验不了：它自己造的字节当然是对的。

## ★ 为什么录的不是「上游 401」

`rec.py` 侧那次 401（错误 Key，R3）**刻意没有进这个目录**：
上游的 401 body 会**回显 Key 片段**。它虽然是假的 Key、虽然 Key 只存在于请求头里、
虽然 `rec.py` 从不记录 `Authorization`，但把一段带 `sk-` 的响应体提交进仓库是没必要的风险。
所以这里四个文件的 `grep -c "sk-"` 与 `grep -ci "authorization\|bearer"` **都必须是 0** ——
换录制文件时请复验这两条。

★★ **复验要拿这四个文件跑，不要拿 `git diff` 跑。** 实测踩过：
在 staged diff 上跑 `grep -ci "authorization\|bearer"` 会命中 **5 行**，
而那 5 行**全是本文件与 `docs/E1-AI能力接入.md` 里描述这条检查的句子** ——
也就是说，**这条判据的说明文字本身在让判据失败**（铁律 8 的第三种形状）。
**判据的对象是那四个文件，不是「包含了这四个文件的 diff」。**

## 重新生成要花多少钱

**不能免费重来。** 生成它们的那两次调用是 E1 全部预算里的 798 token（`519 + 279`）。
`r2-audit.json` 那个「不包围栏」的结论**样本量是 1** ——
它证明的是「这一次没包」，**推不出「真实模型不会包」**。
所以 `fake-openai.py` 的 `json-fence` 故障注入**必须保留**：那是解析器剥围栏能力的对照组。
